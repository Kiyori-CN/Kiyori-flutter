# AI 与扩展设计

## 助手运行

`Conversation` 保存有序消息；`Run` 保存一次执行；工具调用独立记录调用 ID、输入摘要、授权决定、结果或错误。provider adapter 负责协议映射，不拥有第二份会话历史。模型能力（流式、图像、工具、上下文限制）由 provider 描述，缺失能力明确报错。

流式文本合并后节流显示，最终消息和工具事件可靠持久化。Run 状态为 `queued → running → waiting_for_permission / waiting_for_tool → completed`，任意可运行阶段可转入 `cancelling → cancelled` 或 `failed`；请求已发但结果不明保留 `outcome_unknown`，恢复时禁止无提示重复副作用。

附件统一用 ResourceRef，按用户选择和模型能力准备内容，不自动上传整个工作空间。上下文预算需要可解释：记录被引用的消息/资源、摘要来源和截断规则，不能悄悄截断却声称完整处理。

## 统一工具契约

每个工具描述包含稳定 ID、版本、输入输出 JSON Schema、所需 capabilities、是否有副作用、取消语义和幂等性说明。工具执行以 principal（用户/AI/扩展）与 workspace 绑定；调用者不能在参数里声明自己已经获得权限。

流程固定为解析 → schema 校验 → 能力检查 → 按风险需要授权 → 服务执行 → 结果脱敏/大小限制 → 审计记录。结果中的文件通过 ResourceRef 返回，大输出可保存为用户可见资源；不能仅截断输出而掩盖完整结果的位置。

## 扩展形态

| 形态 | 内容与生命周期 | 明确边界 |
| --- | --- | --- |
| Script | 单次程序与输入，使用公开 SDK | 不默认具备进程、网络、文件或密钥访问 |
| Plugin | manifest、版本、入口、资产、声明能力与工具；安装/启停/卸载 | 初期不加载任意原生动态库，不直接进入 Flutter widget 树 |
| Skill | 标准 SKILL.md、references、assets、可选 scripts | 按需加载知识，执行脚本仍走 Script/工具授权 |
| MCP | 外部服务器暴露工具、资源、提示词的协议 | 服务器声称“安全”不等于被授权，结果不能修改宿主策略 |

建议扩展 manifest 字段为 `id`、`version`、`sdkVersion`、`entry`、`capabilities`、`tools`、`integrity`；版本兼容拒绝应先于执行。SDK 接入后发布正式 JSON Schema 与夹具，本阶段不把草案标成稳定公开 API。

## 执行与安装边界

TypeScript 在开发机编译，应用载入受支持的 JavaScript。执行器选择以三端可用、可中断、内存限制、宿主 API 收敛为验收条件，先做 spike 再锁定依赖。Windows 可通过子进程提升故障隔离；移动端没有同等进程能力，不能把线程或 isolate 称为安全沙箱。

每次运行限制时长、内存、输出、并发与允许目标，权限按具体路径、域名或工具范围授予。压缩包安装检查路径穿越、符号链接、体积与数量、摘要和 manifest；先写临时目录再原子切换。来源/签名只证明出处与完整性，不能替代权限控制。

卸载先阻止新调用，再终止活跃任务、撤销授权和解除注册；用户数据按明确选择保留或清除。插件热更新必须等待旧版本执行结算，不能运行中覆盖代码。

## MCP 与 Skill 兼容

MCP 基线依据官方稳定规范 **2026-07-28**，连接必须实际协商版本和能力，不能对所有服务器强制一个版本。优先远程 Streamable HTTP；stdio 仅在支持启动本地进程的平台启用。HTTP 认证、服务器 URL 验证、重定向凭据边界、取消和通知处理都需专门夹具。

Windows 的 stdio 连接需要用户配置可执行程序与参数，不通过拼接 shell 字符串启动。Android 不假设有 Node/Python，iOS 不承诺本地 stdio server。第三方 MCP 服务由用户选择，配置文件中存凭据引用而非 token。

Agent Skills 以官方目录与 frontmatter 规范为基础，宿主私有字段放独立 metadata，不篡改 `SKILL.md` 的标准语义。相对引用必须限制在包根内。工具提示和网页内容按不可信输入处理，不能把其中命令自动升级成宿主操作。

## 验收场景

至少覆盖拒绝授权、撤销后续访问、循环工具调用上限、流断线、重复事件、取消等待、恶意参数/路径、超大返回、脚本超时、MCP 断连、工具列表变化和不兼容扩展。需要跨进程/平台能力时在对应环境实测，不以 mock 代替。
