# 数据与权限设计

本文区分长期存储/权限设计与已实现切片。现有 SQLite、凭据引用和审计保护见 ADR 0005、0006、0015（[决策导航](../README.md)）；统一授权服务、全量备份与浏览器 profile 仍按[状态](../status.md)推进。

## 存储分区

| 数据 | 权威存储 | 规则 |
| --- | --- | --- |
| 会话、任务、资源引用、配置 | Rust 管理的 SQLite | 版本化 migration、事务、索引和错误诊断 |
| 附件和导入资源 | 应用私有 blob 或授权外部位置 | 内容与元数据分开，引用计数/回收需可恢复 |
| API key、MCP token、代理凭据 | Android Keystore 保护的存储、iOS Keychain、Windows 安全存储 | 数据库只保存用途和安全存储引用 |
| 浏览器 Cookie、网页存储 | 平台引擎隔离 profile | 不在核心建立未经维护的 Cookie 副本 |
| 缓存、缩略图、规则编译产物 | 可重建缓存目录 | 明确配额与清理，不删除用户原始数据 |
| 日志与导出诊断 | 本地受限日志目录 | 默认脱敏、限大小/期限，外发由用户主动选择 |

一个数据库写入协调入口，事务尽量短，不在持有数据库锁时等待网络或 UI。后台 OS 回调按稳定 task ID 对账，写入失败必须可诊断。数据库加密方案与备份密钥管理在需要保护完整数据库时专项决定，不能把使用 SQLite 宣称为全库加密。

## 权限模型

能力可用性分 `available`、`unsupported`、`needs_setup`；授权分未询问、允许、拒绝、撤销；执行状态单独记录。有效授权由 principal、workspace、capability、资源范围、时效和授权代次共同决定。

副作用执行前检查授权，长运行在关键边界检查撤销；撤销后阻止新副作用并通知现有任务终止。已发生的网络提交不能被描述为已撤销，结果未知保留事实。

工具返回、网页、远程 MCP、Skill 和插件描述均是非可信输入。它们可提供建议和数据，但不能更改系统提示、授权、文件范围、代理凭据或安装配置。类型校验、路径规范化、origin 检查与 OS 隔离需共同实施。

## 迁移和回滚

schema 迁移单调编号、在事务边界执行；风险迁移前产生一致备份并校验可恢复。旧二进制发现更高 schema 时拒绝写入，避免“回滚安装包”损坏新数据。配置也需版本，未知字段保留策略在公开协议中定义。

新旧应用数据完全隔离；迁移仅通过未来显式导出/导入。导入包需版本、大小限制、路径限制、摘要、预览与冲突处理，凭据默认不导出。跨设备同步不是当前存储实现的隐含职责。

## 依赖与供应链

直接依赖优先官方/维护良好项目，记录版本、许可证、原生二进制来源、平台支持与替换难度。新依赖以实际需求为理由；原生库、脚本 runtime 和媒体库必须核验移动端分发许可与可构建性。

不把第三方源码复制进业务目录；确需补丁先用依赖覆盖并记录上游引用、修复原因、许可证和退出条件。对外发布前建立适配实际依赖的许可证清单/SBOM；工作流存储依赖与许可见[ADR 0005](../decisions/0005-runtime-sqlite-storage.md)，不把本地Debug构建视为发布审查完成。

## 错误、日志与诊断

错误提供 stable code、trace ID、阶段、重试条件和用户可理解原因；日志不打印认证 headers、Cookie、私密文件正文或完整提示词。调试详情通过显式诊断模式采样，保存有期限，导出前可预览。崩溃报告默认本地，不预接遥测服务。
