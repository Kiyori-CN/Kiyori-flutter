# ADR 0002：交互性能与模块边界

状态：采纳；2026-10-02。补充 ADR 0001，不替换 Flutter/Rust 选型。

## 背景

用户反馈三页滑动不如旧 Compose 应用流畅。新项目仍是轻量 UI/运行时骨架，源码已有
首滑构建、每帧重建底栏、输入全页刷新，以及 feature 反向引用 app 的问题。
模块设计遗漏了旧项目数个领域，未来扩大 UI 和业务规模会放大这些风险。

## 选择

保留单 PageView、系统手势仲裁和 Flutter 官方渲染链；首帧后准备三个轻量页面、缩小更新
范围，建立 Profile 测量入口。保持模块化单体，按领域扩展 Rust 服务和 Dart 展示，原生
句柄由 adapter 拥有。迁移地图覆盖旧模块，但不照搬旧双包根与原生库布局。

## 比较与代价

| 方案 | 正确性/维护与成本 | 判断 |
| --- | --- | --- |
| 先去除已证实的重复工作，再 Profile 测量 | 变更小、可回归，保留框架可访问性；缓存增加三个轻量页的内存 | 采用 |
| 自写全屏原始触摸/第二分页控制器 | 需重做 arena、取消、多指、文本选择、无障碍；易制造死区和双 owner | 当前没有必要性证据 |
| 全部更换原生/KMP UI | 重新迁移三端 UI、测试与工具链；不能据此保证零掉帧 | 只有真实平台性能瓶颈无法解决时重新评估 |
| 大量拆 package/crate 与全局状态框架 | 初期增加装配、构建和 API 成本；并不自动降低每帧工作 | 按实际独立边界渐进拆分 |

## 约束与回滚

缓存不能触发网络/数据库扫描；长期任务不依附页面 build；不能通过零手势阈值制造表面
“灵敏”，不能把真实业务错误藏到空页面。保留原几何和未接入空点击。
若缓存导致首帧、内存、无障碍或焦点退化，可以单独撤销预热，不影响唯一 PageController
及状态结构。Flutter 3.47.5 保留在版本目录，可恢复旧 pin 后重新构建。

验收以[性能契约](../development/performance.md)、行为测试及实际构建为准。
未取得真机 trace 前不宣布触摸延迟/掉帧已彻底解决，也不承诺 Flutter 与 Compose 动画逐帧一致。
