# 文档维护规范

文档帮助读者定位事实、执行正确命令并理解限制。本规范参考旧 Kiyori-Android 的文档职责和排版原则，沿用本仓库的英文短横线路径及现有检查入口，不迁入旧仓库的目录生成器或 Gradle 流程。

## 职责与阅读路径

| 载体 | 内容 | 不放入的内容 |
| --- | --- | --- |
| 根 README | 项目定位、能力概览、上手和导航 | 控件清单、单批测试数字与实现流水账 |
| AGENTS | 工作约束、复刻基线、验证和交付规则 | 产品功能说明、长期过程日志 |
| CONTEXT | 高频术语、唯一所有者和不变量 | 全量领域契约与当前任务进度 |
| user-guide | 用户操作、实际结果与功能限制 | 内部调用链和开发检查日志 |
| architecture / design | 架构、模块、长期行为与方案 | 无日期的历史状态、隐式实施承诺 |
| decisions | ADR：问题、选择、取舍、兼容及验收边界 | 把候选方案写成已验证结果 |
| development | 开发入口、工具链、验证策略与测试索引 | 每轮追加的完整命令输出 |
| status / roadmap | 当前任务和证据 / 长期顺序及完成信号 | 互相复制滚动变化的进度 |
| status-history* | 有日期、版本和限制的历史证据 | 当前授权或未经复核的最新状态 |

新增语义只维护所属权威小节，其它入口链接过去。`docs/README.md` 是完整导航；页内目录仅导航本页，不成为第二套文档索引。

## 文件与排版

- 中文正文，路径、类型、API、命令和协议保留准确拼写。文档与脚本使用 `lower-kebab-case`，固定入口保留 `README.md`、`AGENTS.md`、`CONTEXT.md` 等标准名称。
- 使用 UTF-8 无 BOM、LF 和末尾换行。每篇一个一级标题，标题不跳级，标题与列表前后留空行；同一标题应能说明本节职责。
- 围栏注明语言并闭合。命令标明工作目录、前置环境、平台、参数及外部副作用；占位符必须明显，不能把带占位符的命令称为可直接执行。
- 表格每行保持同一物理行，列数一致；单元内的管道写成 `\|`，包括行内代码。复杂过程使用段落或顺序列表，不挤入过宽的表格。
- 长文按主题分节并提供二级标题导航；历史正文保留原日期、命令、测试数量、提交和哈希，整理不更改证据含义。
- 优先相对链接；本机路径仅用于明确的本地来源或操作说明。移动文件同步链接、页内导航、裸路径和脚本消费者；第三方许可证、协议夹具和生成文件保持原格式。

## 事实与状态

`计划` 表示目标；`已实现` 表示存在代码与接线；`已验证` 必须说明证据层级；`待验证` 写清缺少的环境或检查。目录存在、可点击页面和 mock 成功不能证明业务已接入。

产品复刻的唯一旧源是 `D:\10_Project\Kiyori-Android`。记录旧提交、源码入口、宿主、资源和状态分支；完整 UI、文案、逻辑与交互遵循 [AGENTS](../../AGENTS.md)，不得由文档整理引入新产品设计。

历史版本和外部资料保留核验日期，不称为永久最新；升级时重新查官方来源。当前结构以 manifest 和源码为准，目标目录需显式标注尚未创建。未编译 iOS 和未运行的设备检查保持待验证。

## 维护与归档流程

1. 检查当前工作树和影响范围，确定读者、修改原因及事实来源。
2. 修改权威文档，精简入口说明并同步导航。优先保留稳定路径；拆分时列清旧内容的新归属，不丢失已知限制。
3. 当前状态保留正在推进的任务、最近证据与下一门槛；旧批次移入有日期的归档并链接，未完成事项仍留在当前状态。
4. 执行 `tools/check-foundation.ps1`；工具实现变化另执行 `tools/test-tooling.ps1` 与 `tools/verify.ps1`。
5. 审阅标题、围栏、表格、链接、内容顺序和窄屏长行；核对源码事实和差异。自动结构通过不能替代可读性与语义审阅。
6. 在当前状态回填实际证据，再按任务授权审计提交；临时报告与预览放入忽略的 `work/`，不把过程脚本变成正式工具。

## 自动检查的能力边界

基础检查维护编码、基本 Markdown 结构、本地文件链接、文档导航覆盖、严格 JSON 语法、PowerShell 语法及既有依赖/版本接线。它不访问外链，也不证明完整 CommonMark 渲染、页内锚点、源码事实或产品保真。依赖方向检查是定向防回归，不是完整依赖图分析。
