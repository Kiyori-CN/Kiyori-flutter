# 开发路线图

## 里程碑与顺序

| 阶段 | 目标与交付 | 完成信号 | 前置依赖 |
| --- | --- | --- | --- |
| M0 工程基础 | 语言、目录、命名、模块契约、版本基线、本机工具验证 | 文档一致，Windows/Android 最小产物和 Rust 链接证据，Apple 缺口明确 | 空 Kiyori 仓库与本机环境 |
| M1 可运行骨架 | Flutter/Cargo workspace，五平台 runner，FRB 命令/事件，能力注册，应用身份 | Android APK + Windows EXE 含 Rust；异步取消/错误/资源释放可测试；iOS 源集与缺口登记 | M0；FRB/原生打包 spike |
| M2 第一条真实闭环 | 会话/配置存储、流式助手、统一工具、文件读取授权 | 人工和 AI 读同一资源，拒绝/撤销/取消/重启恢复正确 | M1；资源与权限服务 |
| M3 浏览与下载 | WebView 适配、多标签、历史/收藏、文件浏览、下载任务和应用网络策略 | Android/Windows 同会话操作、断点/后台恢复、平台能力明确；iOS 同步适配设计/源集 | M2；原生 WebView 与后台任务 spike |
| M4 媒体与拦截 | 音视频共用播放服务、队列、规则订阅/站点豁免 | 媒体生命周期、音频焦点与拦截诊断有真实平台证据 | M3；媒体依赖与规则编译 spike |
| M5 扩展体系 | TS SDK、脚本、插件包、Skill、MCP 客户端 | 安装/撤权/取消/恶意输入场景通过，能力无旁路 | M2 工具权限成熟；执行器选择 |
| M6 高级平台能力 | 终端、受控本地 MCP、系统代理/VPN（按平台可行范围） | 隔离、权限、退出恢复与数据边界通过平台验收 | 对应平台能力/分发条件；不阻塞基本工作台 |
| M7 发布准备 | Release 签名、迁移/备份、安装器、性能、隐私与依赖归属 | Android/Windows 用户验收；iOS 有 Apple 构建/真机/签名证据后独立达到发布条件 | 所有目标功能达到证据门槛 |

阶段可按依赖调整，不用月份或主观百分比承诺不确定工作量。每阶段只建立真实需要的目录；失败的技术 spike 应先修订 ADR，再扩展业务。

## iOS、macOS 与 Linux 准备轨道

M1 起共享接口考虑五平台；每个模块记录对应实现与缺口。Android/Windows 是当前强制构建目标，iOS/macOS/Linux 先完成工程准备，再分平台取得编译、运行与业务验收证据。取得 Mac 是 iOS 编译的硬依赖，可在任一阶段补齐；没有 Apple 验证不能进入 iOS 发布准备。首个可用 Mac 应优先消除已有构建缺口，而非继续堆积未编译代码。

## 实施顺序与阶段门槛

实际进度只由[当前状态](status.md)维护。M0/M1 已有本机实现与验收证据，M2 的存储、模型、
文字会话与知识切片已经落地；不能把尚未闭合的完整工具/附件链路与已实现基础一起写成“未开始”。
跨阶段先行实现的下载、脚本或提供方包，也不等于 M3/M5 全部完成。

后续推进采用垂直切片：旧入口与嵌套交互 → 唯一 Rust 所有者 → 类型化桥接与平台适配 →
错误/取消/重开回归 → 对应平台验收。完整复刻的来源和差异记录见[复刻流程](development/ui-replication-workflow.md)。
五图标底栏及其它产品设计保持旧源语义。

M2 的剩余完成信号是人工与 AI 使用同一授权资源和工具，覆盖拒绝、撤销、取消、
未知结果与重启恢复。现有 SQLite、模型与会话直接复用；不重新建立数据库或请求运行时。
已授权的本地验证先用合成协议夹具，真实供应商和设备验收按指定范围执行。

M3–M6 的技术 spike 先验证唯一浏览会话、原生视图生命周期、媒体许可与后台释放、
扩展宿主权限和系统代理恢复，再扩展功能；未通过时修订 ADR。CI 单独接线，
提交推送不自动授权创建远端工作流。M1 历史证据见[工程骨架记录](development/m1-foundation.md)。

性能从 M1 起持续验收：首滑、长流式对话、大目录、原生视图与阅读画布均需 Profile
真机基线。Debug、mock、本机截图不能替代这些完成条件。

## 旧项目完整能力的后续轨道

这些是明确规划，不预建空目录；来源与边界见[旧模块地图](architecture/legacy-module-map.md)。

| 轨道 | 前置与首次交付 | 后续完成条件 |
| --- | --- | --- |
| 文档工作台 | M2 files/storage 后：文本打开、草稿、可靠保存 | M3–M4 按格式补 TXT/EPUB/PDF/Office，虚拟画布与旧 UI/完整正文验收 |
| 记忆与知识 | M2 storage/permissions 后：空间、CRUD、归档 | 向量指纹/取消/重建、关系、来源引用与版本化导入 |
| 工作流 | M2 tools 后：顺序节点、取消/失败 | M5 调度/恢复、编辑器、未知结果不重复执行 |
| 账号与内容 | M3 network/browser 后：账号验证与内容查询 | M4 B站五栏、音乐来源、歌词、共享下载与播放 |
| 语音与形象 | M2 assistant 之后逐项验证平台后端 | 麦克风/音频租约、离屏暂停、纹理与后台释放；不阻塞首条助手闭环 |
| 备份/审计 | 随 M2 持久化建立 schema/安全边界 | M7 完整校验恢复、密钥边界、历史导入；早期不能无恢复方案堆数据 |
| 系统自动化/外部集成 | M6 平台能力与来源认证 | 窗口/显示/进程取消、撤权、HTTP/Intent/Tasker 等入口逐项验证 |
