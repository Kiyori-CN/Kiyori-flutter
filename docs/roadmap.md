# 开发路线图

## 里程碑与顺序

| 阶段 | 目标与交付 | 完成信号 | 前置依赖 |
| --- | --- | --- | --- |
| M0 工程基础 | 语言、目录、命名、模块契约、版本基线、本机工具验证 | 文档一致，Windows/Android 最小产物和 Rust 链接证据，Apple 缺口明确 | 空 Kiyori 仓库与本机环境 |
| M1 可运行骨架 | Flutter/Cargo workspace，三端 runner，FRB 命令/事件，能力注册，应用身份 | Android APK + Windows EXE 含 Rust；异步取消/错误/资源释放可测试；iOS 源集与缺口登记 | M0；FRB/原生打包 spike |
| M2 第一条真实闭环 | 会话/配置存储、流式助手、统一工具、文件读取授权 | 人工和 AI 读同一资源，拒绝/撤销/取消/重启恢复正确 | M1；资源与权限服务 |
| M3 浏览与下载 | WebView 适配、多标签、历史/收藏、文件浏览、下载任务和应用网络策略 | Android/Windows 同会话操作、断点/后台恢复、平台能力明确；iOS 同步适配设计/源集 | M2；原生 WebView 与后台任务 spike |
| M4 媒体与拦截 | 音视频共用播放服务、队列、规则订阅/站点豁免 | 媒体生命周期、音频焦点与拦截诊断有真实平台证据 | M3；媒体依赖与规则编译 spike |
| M5 扩展体系 | TS SDK、脚本、插件包、Skill、MCP 客户端 | 安装/撤权/取消/恶意输入场景通过，能力无旁路 | M2 工具权限成熟；执行器选择 |
| M6 高级平台能力 | 终端、受控本地 MCP、系统代理/VPN（按平台可行范围） | 隔离、权限、退出恢复与数据边界通过平台验收 | 对应平台能力/分发条件；不阻塞基本工作台 |
| M7 发布准备 | Release 签名、迁移/备份、安装器、性能、隐私与依赖归属 | Android/Windows 用户验收；iOS 有 Apple 构建/真机/签名证据后独立达到发布条件 | 所有目标功能达到证据门槛 |

阶段可按依赖调整，不用月份或主观百分比承诺不确定工作量。每阶段只建立真实需要的目录；失败的技术 spike 应先修订 ADR，再扩展业务。

## iOS 同步轨道

M1 起所有共享接口和核心用例考虑 iOS；每个模块记录 Apple 对应实现与缺口。取得 Mac 是 iOS 编译的硬依赖，可在任一阶段补齐；没有 Apple 验证不能进入 iOS 发布准备。首个可用 Mac 应优先消除已有构建缺口，而非继续堆积未编译代码。

## 当前下一步

当前执行顺序为公共组件与全部12项设置子树 → 设置本地验收 → AI左抽屉及关联页面、
真实业务垂直切片 → AI其余旧源确认功能，详见[实施方案](design/ui-replication-plan.md)。
设置阶段覆盖非默认态、弹层及来源返回；完成本地验收后立即推进M2，不等待所有独立
工作台先做完UI。AI阶段按依赖同时实现Dart投影和Rust业务，不能用空点击代替业务完成。

复用已有首页、一级页面和设置成果；当前重点是完整设置子树及其公共组件，契约见
[UI复刻](design/ui-parity.md)。五图标底栏几何保持不变；改变架构不等于重新设计产品。

性能从 M1 起持续验收，不等 M7：首滑与热滑、长流式对话、大目录、原生视图和阅读画布分别
建立 Profile 真机基线。2026-10-02 的工程基础/滑动专项补齐模块地图与测试入口；现场结果
仍按 [status](status.md) 的证据等级解释。

M1 的实施与验收细化见 [M1 计划](development/m1-foundation.md)。之后按以下小步骤推进 M2，当前状态只在 [status.md](status.md) 维护：

1. **资源与授权基础**：类型化 ResourceRef、workspace 范围、调用来源与授权撤销，覆盖路径/URI 差异；完成信号是纯核心契约与平台 adapter 的实际文件读取测试。
2. **SQLite 与迁移**：会话、资源引用和配置的单一持久化入口；完成信号是初始建库、重启恢复、事务失败与迁移恢复测试。
3. **统一工具调用**：schema、权限、错误、取消与审计摘要；完成信号是手动与助手路径使用同一服务，无权限绕行。
4. **首个模型接入**：流式消息与一次授权文件读取；先使用本地协议夹具验证，再在用户配置凭据并授权后进行真实 API 验收，覆盖断流和副作用结果未知。
5. **阶段交付**：Android 设备验证需用户指定并授权；Windows 完成实际交互；iOS 按可用 Apple 环境推进。首次提交/推送时再接入与本机入口一致的 CI，不擅自触发远端任务。

M3–M6 的技术 spike 必须先于大规模功能实现：浏览器查唯一会话/平台视图生命周期，媒体查许可/硬解/后台，扩展查取消/资源限制与宿主权限，系统代理查影响范围和退出恢复。任何一次 spike 不通过都先修订方案，不能用静默回退掩盖。
