# Kiyori

Kiyori 是正在从零构建的个人跨平台 AI 工作台，面向 Android、Windows 与 iOS。它计划把 AI 助手、网页浏览、文件与下载、音视频和可授权的扩展工具统一到一个应用中。

**界面沿用旧 Kiyori：中央首页、左侧负一屏、右侧 AI 对话和五图标底栏。** 底栏可打开浏览器、工具箱、文件管理与设置一级页面；浏览器顶栏返回恢复入口，其他一级页面系统返回回到首页。工具箱分组可展开/折叠，其余未接入业务的按钮保留外观与空点击。重构主要改善目录与内部实现，并支持多平台。真实 Rust 核心及开发用运行检查已建立。Android 与 Windows 优先实现和验证；iOS 已维护源集，Apple 平台构建和设备验收需要后续补齐 Mac 与测试设备。

## 阅读入口

AI页左侧菜单可打开抽屉，切换AI工具箱、工作流与设置并保持聊天草稿。
工作流已接入本机SQLite定义目录，可新建、编辑名称/描述/启用状态、重开读取与确认删除。
数据保存在新应用Application Support目录，不读取旧Android数据库；存储失败显示错误。
模板、节点、执行、调度和扩展业务仍待实现，启用定义不表示后台任务已开始运行。
记忆库可管理本机空间和目录、新建/编辑手工记忆与知识笔记、归档/恢复和确认删除。
列表按100条分页，搜索由本机Rust存储执行；列表摘要不改变完整正文。删除文件夹保留正文
并移到根目录，删除空间会删除其中条目；默认空间不可删除。日记支持开篇阶段、时间线、
追加进展、收尾和全文编辑，列表可筛选进行中/已完结；归档后需恢复才能续写。续写成功后
才清空草稿，离开或切换全文编辑前确认未保存内容。文档导入、图谱、云端嵌入和AI自动
记忆尚未接入，不会因打开记忆库而外发正文。

设置中的网页浏览器、文件下载器、文件管理器、视频/音乐播放器和工具箱可进入复刻子页；
文件管理和工具箱顶栏也可进入同一设置页面。视频包含字幕、声音、弹幕、控制栏页面，
工具箱包含常用、分组管理和文档设置。音乐包含音源、下载和歌词等偏好页面。
更多功能已接入存储路径、产物目录和网络代理页面；广告拦截包含规则与订阅浏览。
数据备份可浏览原卡片与选择弹窗；更多功能中的权限、协议与开源页面已接入阅读外观。
主题设置可浏览主题、背景、聊天、输入栏与 AI 界面五标签，颜色和样式预览仅保留页面草稿。
界面定制父页还包含语言、全局显示和布局调整；这些页面的开关、数值和预览均为本地草稿，
不会改变系统语言、通知、后台服务或文件路径。
更多功能可重新查看六页引导；阅读、翻页和权限选择仅保留本次预览，完成后返回设置。
数据备份下的聊天历史管理已接入五张统计/批量卡片与归类、删除、记忆重建日期弹层；
默认为空展示快照，不扫描聊天库或工作区，筛选与选择仅保留页面草稿。
AI 助手中的上下文与总结可预览数值、依赖开关、总结规则及历史媒体重置弹窗，尚不写模型配置。
功能模型分配已保留11项功能卡片与两层选择；可用配置由后续快照提供，测试按钮为空操作。
模型与 API 已接入默认配置、提供方/协议抽屉、模型标签排序、上下文/总结折叠卡、参数四标签、
请求头和高级设置预览。表单仅保留本次草稿，连接、保存、下载和导入导出尚未接入。
角色卡和提示词可进入三标签工作台，预览默认 Kiyori、角色/标签编辑、放大编辑、排序与
模型/记忆/工具绑定弹层。嵌套编辑确认只回填本次草稿；最终保存、创建、复制、删除、

AI 工具授权包含全局三态、允许/禁止例外与搜索选择；选择只改变页面草稿，不授予权限。

语音唤醒包含识别模式、个人模板弹窗、超时/反馈/分组及四类自动附加项；录音、监听和
附件抓取为空操作，修改关键词和开关仅保留页面草稿。
详情返回保留原入口；弹窗、选择抽屉与预览可交互，
保存和系统操作仍为空点击。
虚拟形象设置已接入预览折叠、完整导入说明，以及注入模型目录后的选择、重命名/删除确认、
情绪绑定/自定义类型编辑和分类型相机参数草稿；没有真实导入或原生渲染器。账号页支持

## 本机准备检查

在已配置受管理环境的 Windows PowerShell 中执行：

```powershell
Set-Location D:\10_Project\Kiyori
. .\tools\activate.ps1
flutter --version
rustc --version
.\tools\check-foundation.ps1
```

其他机器的安装要求见工具链文档。当前支持的本机构建与运行入口：

```powershell
flutter pub get
.\tools\test-ui.ps1 -Test home_shell_test.dart,primary_pages_test.dart
.\tools\verify.ps1
.\tools\build.ps1 -Platform android
.\tools\build.ps1 -Platform windows
.\tools\build.ps1 -Platform android -Mode profile
Set-Location apps\kiyori
flutter run -d windows
```

Android Debug 产物在 `apps/kiyori/build/app/outputs/flutter-apk/app-debug.apk`；Windows 在 `apps/kiyori/build/windows/x64/runner/Debug/`，运行时需保留整个目录及其 DLL/data。安装到设备另行进行。

性能排查使用 `-Mode profile`（Android 产物为同目录 `app-profile.apk`），不要据 Debug 判断
真机手感。三页往返基准、真实触摸验收与高刷帧预算见[性能契约](docs/development/performance.md)。
`build/verify` 会检查实际 Flutter/Dart/Rust 版本，当前 pin 为 Flutter 3.47.6 / Dart 3.13.5。
每个新 PowerShell 会话都先运行 `tools/activate.ps1`。同一批验证中，依赖已经解析且
manifest/lock 未变化时，`tools/test-ui.ps1` 与 `tools/build.ps1` 可追加 `-NoPub`，避免重复
解析依赖；首次运行或依赖变化后仍使用默认入口。

修改 Rust 公共 API 后运行 `tools/generate-bridge.ps1`。生成器安装、真实桥接测试和 iOS 限制见 [M1 开发指南](docs/development/m1-foundation.md)。

开发时可在 `apps/kiyori` 执行 `flutter run -d windows --dart-define=KIYORI_DIAGNOSTICS=true` 进入独立运行检查。正常启动保持复刻界面，设置按钮不跳转到开发诊断页。UI 的源码依据和验证范围见 [UI 复刻契约](docs/design/ui-parity.md)。

## 项目身份

产品和新仓库均命名为 **Kiyori**，内部包使用 `kiyori` 前缀。新 Android 应用使用 `com.kiyori`，与独立维护的旧 Android 应用并存。详细标识见[命名规范](docs/architecture/naming.md)。
